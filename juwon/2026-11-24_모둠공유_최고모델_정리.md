## 2. 최종 모델 구조 (E58)

```
[피처 35개 만들기]
        │
        ├─ 목·금 행 (전체의 72%)
        │     ① 기본 모델  = LightGBM × 0.8 + CatBoost × 0.2   (대회 train 전체로 학습)
        │     ② 평일 전용 = LightGBM                           (대회 월·화·수만 학습)
        │     → 목·금 예측 = ① × 0.5 + ② × 0.5
        │
        └─ 일요일 행 (전체의 28%)
```

## 3. 핵심 아이디어 4개 (발표용)

### 3-1. 일요일: 진짜 일요일 데이터로 배우기 (E35 → E58, 가장 큰 개선)

- **문제:** 대회 학습 데이터는 월·화·수·토뿐이고 일요일이 없음. 평가에는 일요일이 28%.
- **처음 방법 (E35):** 일요일을 "토요일처럼"과 "평일처럼" 두 번 예측해서 반반 섞음 → −0.22
- **그래도 남은 문제:** 연습 데이터로 보니 일요일 오차가 평일보다 3.5초 큼 (목·금 26.07, 일 29.54). 모델이 일요일을 실제보다 길게 예측함.
- **해결 (E58):** 연습 데이터의 test에는 진짜 일요일 정답이 있음 → 연습 데이터 전체를 학습에 추가하고 "일요일인가" 피처를 넣음.
- **검증:** 연습 노선 하나를 빼고, 나머지 노선의 일요일로 학습해서 빠진 노선의 일요일을 맞힘 (대회 노선처럼 "일요일을 처음 보는 노선" 상황).

| 연습 노선 | 일요일 MAE (전 방법) | 일요일 MAE (E58 방법) | 차이 |
|---|---|---|---|
| 1 | 35.724 | 33.981 | −1.743 |
| 102 | 28.472 | 26.659 | −1.813 |
| 511 | 27.665 | 25.772 | −1.893 |
| 605 | 28.803 | 26.695 | −2.108 |
| 합계 | 29.459 | 27.577 | **−1.882** |

- 4개 노선 모두 좋아짐. 목·금은 이 모델이 오히려 나빠서(26.112 → 26.407) **일요일에만 씀**.
- 대회 public: 24.555 → **24.309**.

### 3-2. 회차 구간(종점 대기) 힌트 (E41)

- **회차 구간:** 노선마다 상행 구간 중 평소 시간이 가장 긴 구간. 종점에서 쉬는 시간이 들어 있음.
  - 행은 0.67%뿐인데 오차의 6%를 차지함 (한 행에 200초 넘게 틀림).
- **아이디어:** 쉬는 시간은 데이터에 없지만, 같은 버스의 **다음 운행(반대 방향)이 몇 시에 시작하는지**는 있음. 오래 쉬면 다음 운행이 다음 시로 넘어감.
  - 다음 운행이 같은 시에 시작 → 회차 구간 중앙값 596초
  - 다음 시에 시작 → 788초
- 이런 힌트 10개를 회차 구간에만 넣음 → public −0.198.

### 3-3. 회차 구간 시간 추정 (E56)

- 한 버스가 한 시간 동안 지나간 구간들의 시간을 다 더하면 거의 1시간임 (중앙값 3,574초).
- 그래서 "1시간 − 같은 시간에 지나간 다른 구간들의 평소 시간 합"으로 회차 구간 시간을 대충 계산할 수 있음.
- 이 값 하나만으로는 부정확하지만, 피처로 넣으니 대회 검증 −0.054, public −0.022.

### 3-4. 목·금은 평일만 배운 모델과 섞기 (E44/E46)

- 월·화·수만으로 학습한 모델을 기본 모델과 반반 섞음.
- 대회 검증(월·화·수 하루씩 빼기): 3일 모두 좋아짐, 평일 −0.072.

## 6. 왜 더 안 줄어드나 (발표 "한계"용)

- 같은 날·같은 구간·같은 시간대에 지나간 **다른 버스들의 실제 시간을 정답으로 알려 줘도** 우리 모델보다 못 맞힘 (25.84 vs 23.21).
- 같은 시간대의 버스끼리도 평균 26초씩 차이 남 → 남은 오차는 **버스 한 대마다의 신호 대기, 승객 승하차, 분 단위 시각** 같은 데이터에 없는 정보 때문.
- 오차 50초 넘는 행 13%가 전체 오차의 절반. 그중 62%는 실제가 더 느림 (기다린 버스).
