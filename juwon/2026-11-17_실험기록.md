연습 데이터(`data/practice/`, 노선 1·102·511·605번)로 검증 틀을 만들고 피처 실험을 진행함.

- 노트북: `bis-travel-time-practice/notebooks/cv_feature_experiments.ipynb`
- 실험 기록 CSV: `bis-travel-time-practice/experiments/results.csv`
- 제출 파일: `bis-travel-time-practice/submissions/practice_base_seg_time_trip.csv`

## 1. 오늘 한 일

1. 환경 세팅: conda `bis` 환경 (Python 3.12) 생성, `requirements.txt` 설치, 맥 LightGBM 오류(`libomp`) 해결
2. 연습 데이터 다운로드 (허깅페이스): train 109,891행 / test 79,942행
3. 데이터 확인 (EDA): 컬럼, 결측, 이상치, 날짜별·시간대별 통행시간
4. 검증 틀 + 피처 실험 노트북 작성, E0~E8 실험 실행
5. 연습 test로 최종 확인 채점

## 2. 검증 방법

**날짜별 4-fold**: train 날짜 4개를 하나씩 검증으로 빼고 나머지 3일로 학습함.

| fold | 학습 | 검증 | 의미 |
|---|---|---|---|
| 1 | 화·수·토 | 월 | 평일 성능 |
| 2 | 월·수·토 | 화 | 평일 성능 |
| 3 | 월·화·토 | 수 | 평일 성능 |
| 4 | 월·화·수 | 토 | 주말 성능 (일요일 예상용) |

- **비교 점수 `예상`** = 평일 평균 × 0.72 + 토 × 0.28 (평가 행 비율: 목·금 72%, 일 28%)
- 무작위 분할을 쓰지 않은 이유: 같은 시각 앞뒤 버스가 섞여 점수가 실제보다 좋게 나옴 (대회 규칙에도 날짜 단위 분할 명시)

## 3. 모델

**LightGBM** (E1~E8 전부 같은 설정). E0은 모델 없는 평균 예측.

| 설정 | 값 | 뜻 |
|---|---|---|
| `objective` | `regression_l1` | 채점 지표인 MAE를 직접 줄이도록 학습 |
| `n_estimators` | 600 | 트리 600개 (검증 점수 부풀림을 막기 위해 early stopping 대신 고정) |
| `learning_rate` | 0.05 | |
| `num_leaves` | 127 | |
| `min_child_samples` | 50 | |
| `subsample` / `colsample_bytree` | 0.8 / 0.8 | |
| `random_state` | 0 | |

## 4. 사용한 피처

| 묶음 | 피처 | 만드는 법 | 가설 |
|---|---|---|---|
| `base` | `route_id`(범주형), `route_type`, `direction`, `interval`, `from_lat`, `from_lon`, `to_lat`, `to_lon`, `dlat`, `dlon`, `stop_seq`, `dist_m`, `arrive_hour`, `is_weekend`, `is_peak` | 교수님 베이스라인과 같음. `interval`은 날짜에 맞는 배차간격(평일/토/일), `is_peak`는 7~9시·17~19시 | 출발점 |
| `seg` | `seg_id`(범주형) | `from_stop + "_" + to_stop` | 신호·정류장 혼잡 같은 구간 고유 특성이 가장 큼 |
| `time` | `first_min`, `last_min`, `hour_from_first`, `is_last_seg`, `seq_from_end` | 첫차·막차를 분으로, 첫차 이후 경과 시간, 노선 마지막 구간 여부, 끝까지 남은 정류장 수 | 끝 구간은 회차 대기로 유난히 김 (중앙값 400~800초) |
| `te` | `te_seg`, `te_seg_hour`, `te_seg_speed` | 학습 날짜로만 계산한 구간별 / 구간×시간대 `tt_sec` 중앙값, 구간 평소 속도. 학습 행 자신은 자기 날짜를 뺀 값(out-of-fold) | 같은 구간의 과거 기록이 가장 좋은 힌트 |
| `trip` | `trip_no`, `seq_in_trip`, `trip_start_hour`, `hours_in_service` | 날짜·차량·노선·방향으로 운행을 묶어 그날 몇 번째 운행인지, 운행 안 몇 번째 구간인지, 운행 시작 시각, 차량 첫 기록 이후 경과 시간 | 운행이 길어질수록 지연이 쌓임 |
| `busy` | `n_bus_hour` | 같은 날·노선·방향·시간대에 기록된 차량 수 | 배차가 많은 시간 = 수요가 많은 시간 |

모든 피처는 test에서도 정답 없이 계산할 수 있음 (`te`는 train 정답으로만 계산).

### base 피처 자세히

`base` = **교수님 베이스라인 노트북에 원래 들어 있던 기본 피처 15개 묶음**. 모든 실험의 바닥 재료로 깔고, 그 위에 다른 묶음을 하나씩 더함.

| 피처 | 뜻 | 어디서 왔나 |
|---|---|---|
| `route_id` | 노선 (범주형) | 원본 컬럼 |
| `route_type` | 노선 유형 (1 급행, 2 간선 등) | 원본 컬럼 |
| `direction` | 상행(0) / 하행(1) | 원본 컬럼 |
| `stop_seq` | 출발 정류장이 노선에서 몇 번째인지 | 원본 컬럼 |
| `dist_m` | 두 정류장 사이 거리(m) | 원본 컬럼 |
| `arrive_hour` | 출발 정류장 도착 시각(시) | 원본 컬럼 |
| `from_lat`, `from_lon` | 출발 정류장 위도, 경도 | 원본 컬럼 |
| `to_lat`, `to_lon` | 도착 정류장 위도, 경도 | 원본 컬럼 |
| `dlat` | 도착 위도 − 출발 위도 (남북으로 얼마나 가는지) | 새로 만듦 |
| `dlon` | 도착 경도 − 출발 경도 (동서로 얼마나 가는지) | 새로 만듦 |
| `is_weekend` | 주말이면 1, 평일이면 0 | 새로 만듦 (`date`에서) |
| `is_peak` | 출퇴근 시간(7~9시, 17~19시)이면 1 | 새로 만듦 (`arrive_hour`에서) |
| `interval` | 그날에 맞는 배차간격 (평일/토/일 중 하나) | 새로 만듦 (`interval_wd/sat/sun`에서) |

원본 컬럼 10개 + 가공해서 만든 피처 5개 = 15개.

실험별 피처 구성:

```
E1 = base                            (15개)
E2 = base + seg                      (+ 구간 ID 1개      → 16개)
E3 = base + seg + time               (+ 시간 정보 5개    → 21개)
E5 = base + seg + time + trip        (+ 운행 순서 4개    → 25개)
E6 = base + seg + time + trip + busy (+ 버스 수 1개      → 26개)
```

### 버린 실험: 구간×주말 중앙값
- 처음엔 `te`에 구간×주말, 구간×주말×시간대 중앙값도 넣었음.
- 토요일 fold에서 학습 날짜(월·화·수)에 주말이 없어 값이 전부 비었고, **토 MAE가 36.2 → 58.8로 망가짐**.
- 그래서 `te`에서 뺐음.

## 7. 알게 된 것

- **구간 ID가 가장 확실하게 효과가 있음.** 구간 고유 특성 가설이 맞음.
- **구간 중앙값(target encoding)은 오히려 나빠짐.** 구간 ID와 정보가 겹치는 것으로 추정.
- **이상치 제거는 효과 없음.** L1 손실이 이미 이상치에 강함. test에도 이상치가 비슷한 비율(600초 초과 0.86%)로 있음.
- **E5와 E6 차이(0.04초)는 잡음 수준.** 최종 제출은 더 단순한 E5로 둠.
- **약점은 주말(일요일).** 평일 26점대, 토 36점대, 연습 test 일요일 30.7. 학습에 주말이 토요일 하루뿐이라서.
- **1번 노선(급행)이 가장 많이 틀림** (33.35초). 구간 거리가 길고 통행시간이 김.
