# E37 적응형 일요일 앙상블

## 1. 한 줄 요약

E37은 일요일의 두 가지 예측인 **토요일처럼 예측한 값**과 **평일처럼 예측한 값** 사이에서, 모든 행을 같은 비율로 섞지 않고 각 행의 특성에 따라 섞는 정도를 다르게 정한 모델이다.

- 기준 제출: `final_E32.csv`
- 이전 개선 제출: `final_E35_sunmix.csv`
- 최종 제출: `final_E37_adaptive_sunmix.csv`
- 최종 파일 생성 코드: `bis-travel-time-practice/scripts/E37_adaptive_sunmix.py`

목요일과 금요일 예측은 E32를 그대로 유지하고, 일요일 행만 적응형 보정을 적용했다.

## 2. 출발점

### E32

E32는 E5 피처 25개를 사용한 다음 두 모델의 앙상블이다.

| 모델 | 비중 | 주요 설정 |
|---|---:|---|
| LightGBM | 0.8 | MAE 손실, `num_leaves=127`, `min_child_samples=10`, `learning_rate=0.02`, 1,500개 트리 |
| CatBoost | 0.2 | MAE 손실, `depth=10`, `learning_rate=0.08`, 2,000회 |

E32의 public MAE는 25.028이었다.

### E35

학습 데이터에는 일요일이 없고 토요일만 있기 때문에, E32는 일요일을 토요일과 비슷하게 예측한다. 이를 보완하기 위해 E35에서는 일요일 행을 다음 두 방식으로 다시 예측했다.

1. 토요일처럼 예측
   - `is_weekend = 1`
   - 토요일 배차 간격 사용
2. 평일처럼 예측
   - `is_weekend = 0`
   - 평일 배차 간격 사용

두 예측을 50:50으로 평균한 것이 E35다.

```text
E35 일요일 예측 = 토요일형 예측 × 0.5 + 평일형 예측 × 0.5
```

E35의 public MAE는 24.808로, E32보다 0.220초 개선됐다.

## 3. E37의 핵심 아이디어

E35는 모든 일요일 행에 같은 50:50 비율을 적용한다. 하지만 구간, 시간대, 노선 유형, 거리 등에 따라 두 예측 중 어느 쪽이 더 좋은지가 다를 수 있다.

E37은 별도의 작은 LightGBM 모델을 사용해 다음 값을 예측한다.

```text
필요한 보정값 = 실제 통행시간 - 토요일형 예측
```

이 보정 모델을 편의상 `게이트 모델`이라고 부른다. 게이트 모델은 최종 통행시간 전체를 다시 예측하는 모델이 아니다. E32의 토요일형 예측에서 평일형 예측 방향으로 얼마나 움직일지만 정한다.

## 4. 학습 데이터

게이트 모델은 정답이 공개된 연습용 데이터의 일요일 행만 사용해 학습했다.

| 항목 | 내용 |
|---|---|
| 데이터 | `data/practice/test.parquet` |
| 대상 요일 | 일요일 |
| 행 수 | 22,376행 |
| 연습 노선 | 1, 102, 511, 605번 |
| 목표값 | 실제 통행시간 − 토요일형 예측 |

대회 test의 정답은 사용하지 않았다.

## 5. 두 기준 예측 복원

연습용과 대회용 모두 E32와 E35 예측 파일을 이용했다.

- `sat`: 토요일형 예측, 즉 E32의 일요일 예측
- `mix`: E35의 50:50 예측
- `wd`: 평일형 예측

E35가 두 예측의 단순 평균이므로 평일형 예측은 다음과 같이 복원할 수 있다.

```text
wd = 2 × mix - sat
delta = wd - sat
```

`delta`는 평일형 예측으로 바꿨을 때 예측값이 얼마나 움직이는지를 나타낸다. 두 예측의 차이가 클수록 해당 행에서 요일 처리 방식에 대한 모델의 불확실성이 크다고 볼 수 있다.

## 6. 게이트 모델 피처

게이트 모델에는 노선 ID나 구간 ID를 직접 넣지 않았다. 연습 노선과 대회 노선이 서로 다르기 때문에 특정 노선을 외우지 않고 구조적인 특징을 학습하게 하기 위해서다.

| 묶음 | 피처 |
|---|---|
| 두 예측 | `sat`, `wd`, `delta`, `abs(delta)` |
| 예측과 거리 | `sat / dist_m` |
| 구간 구조 | `dist_m`, `stop_seq`, `direction` |
| 시간 | `arrive_hour` |
| 노선 성격 | `route_type` |
| 배차 | `interval_wd`, `interval_sat`, `interval_sun` |
| 공간 위치 | 출발·도착 위도와 경도 |

전체 피처는 17개다.

## 7. 게이트 모델 구성

과적합 위험을 줄이기 위해 설정이 조금씩 다른 LightGBM 세 개를 평균했다.

공통 설정은 다음과 같다.

| 설정 | 값 |
|---|---:|
| 손실 함수 | `regression_l1` |
| 트리 수 | 200 |
| 학습률 | 0.03 |
| `min_child_samples` | 100 |
| `reg_lambda` | 10 |
| random seed | 0 |

세 모델은 `num_leaves`만 각각 7, 15, 31로 다르다.

```text
게이트 원시 보정값
= LightGBM(leaves=7) 예측 / 3
+ LightGBM(leaves=15) 예측 / 3
+ LightGBM(leaves=31) 예측 / 3
```

## 8. 안전장치

게이트 모델이 연습 데이터의 패턴을 잘못 일반화해 과도한 값을 만들지 않도록 두 가지 제한을 적용했다.

### 두 기준 예측 사이로 제한

최종 예측은 반드시 토요일형 예측과 평일형 예측 사이에만 위치하게 했다.

```text
최종 예측 ∈ [min(sat, wd), max(sat, wd)]
```

즉 게이트 모델은 이미 만들어진 두 예측 사이의 선택만 할 수 있고, 두 예측 범위 밖으로 외삽할 수 없다.

### 보정 폭 제한

행 하나의 보정값은 최대 ±150초로 제한했다.

```text
-150 ≤ 보정값 ≤ 150
```

연습 노선 홀드아웃 검증에서 제한이 없을 때의 일요일 MAE는 28.774였고, ±150초 제한을 적용했을 때 28.756으로 조금 더 좋아졌다.

## 9. 검증 방법

게이트 모델을 같은 노선에 학습하고 평가하면 특정 노선을 외워서 점수가 좋아질 수 있다. 이를 막기 위해 연습 노선 하나를 통째로 제외하는 검증을 사용했다.

예를 들어 1번 노선을 평가할 때는 102, 511, 605번으로만 게이트 모델을 학습했다. 이 과정을 네 노선에 대해 반복했다.

```text
Fold 1: 102·511·605 학습 → 1 평가
Fold 2: 1·511·605 학습 → 102 평가
Fold 3: 1·102·605 학습 → 511 평가
Fold 4: 1·102·511 학습 → 605 평가
```

이 검증은 연습 노선과 겹치지 않는 대회 노선에 게이트 모델을 적용하는 상황을 모의한다.

## 10. 검증 결과

### 일요일

| 방법 | 일요일 MAE |
|---|---:|
| E32 토요일형 예측 | 30.491 |
| E35 고정 50:50 혼합 | 30.212 |
| **E37 적응형 혼합** | **28.756** |

E37은 E32보다 1.735초, E35보다 1.457초 좋아졌다.

### 연습 test 전체

목요일과 금요일은 E32 예측을 그대로 유지하고 일요일만 바꿨다.

| 방법 | 전체 MAE | 목요일 | 금요일 | 일요일 |
|---|---:|---:|---:|---:|
| E32 | 27.473 | 25.600 | 27.003 | 30.491 |
| E35 | 27.395 | 25.600 | 27.003 | 30.212 |
| **E37** | **26.987** | **25.600** | **27.003** | **28.756** |

노선 홀드아웃 검증에서 네 개 연습 노선이 모두 개선됐다.

## 11. 대회 제출 파일 생성

최종 게이트 모델 세 개는 연습용 일요일 네 노선 전체로 학습했다. 이후 대회 일요일 행의 보정값을 예측했다.

최종 제출 파일 구성은 다음과 같다.

```text
목요일·금요일: E32 예측 그대로
일요일: E32 토요일형 예측 + 적응형 보정값
```

최종 파일의 특징은 다음과 같다.

| 항목 | 값 |
|---|---:|
| 전체 행 | 111,563 |
| 일요일 행 | 30,848 |
| E32와 달라진 행 | 17,466 |
| 결측값 | 0 |
| 중복 `row_id` | 0 |
| 목·금 변경 행 | 0 |

대회 일요일 보정값의 중앙값은 0초다. 절반 이상의 일요일 행은 E32 예측을 사실상 유지하고, 게이트 모델이 효과가 있다고 판단한 행만 움직인다.

## 12. 대회 학생용 데이터 전이 검증

대회 학생용 train에는 일요일 정답이 없으므로 E37의 일요일 성능을 직접 계산할 수 없다. 대신 토요일을 이용해 같은 구조의 전이 검증을 추가했다.

검증 절차는 다음과 같다.

1. 연습용과 대회 학생용에서 토요일을 모두 학습에서 제외한다.
2. 월·화·수 데이터만으로 E32의 LightGBM과 CatBoost를 다시 학습한다.
3. 토요일 행을 토요일형과 평일형으로 각각 예측한다.
4. 연습용 토요일 정답으로 적응형 게이트를 학습한다.
5. 게이트를 대회 학생용의 서로 다른 5개 노선 토요일에 적용한다.
6. 대회 학생용 토요일 실제 정답으로 MAE를 계산한다.

모든 대회 토요일 예측은 해당 날짜를 학습에서 완전히 제외한 날짜 OOF 예측이다. 새로 재학습한 E32 토요일형 예측은 저장된 `oof_final_E32.parquet`과 최대 절대 차이 0으로 일치했다.

### 전체 결과

| 방법 | 대회 학생용 토요일 MAE | E32 대비 |
|---|---:|---:|
| E32 토요일형 | 30.488655 | 0 |
| 고정 70:30 혼합 | 30.475893 | -0.012762 |
| 고정 50:50 혼합 | 30.472849 | -0.015806 |
| **적응형 게이트** | **30.470944** | **-0.017711** |

적응형 게이트의 개선 폭은 연습 일요일 검증보다 작았지만, 대회 학생용에서도 성능이 나빠지지 않았고 고정 혼합보다 가장 낮은 MAE를 기록했다.

### 노선별 결과

| 노선 | E32 토요일형 | 적응형 게이트 | 차이 |
|---|---:|---:|---:|
| 2 | 44.825 | 44.823 | -0.002 |
| 211 | 26.813 | 26.783 | -0.030 |
| 311 | 30.542 | 30.534 | -0.008 |
| 704 | 25.353 | 25.353 | 0.000 |
| B1 | 29.989 | 29.905 | -0.084 |

다섯 노선 모두 악화가 없었고, 연습 데이터에 없던 광역 유형의 B1 노선에서 가장 크게 개선됐다. 이는 게이트가 특정 연습 노선 ID를 외운 것이 아니라 두 예측의 차이와 거리·시간·배차·공간 특성을 이용했다는 근거가 된다.

다만 이 검증은 토요일에서 수행한 대리검증이다. 일요일은 토요일과 교통 패턴이 다르므로, 대회 일요일에서 연습 검증과 같은 1초 이상의 개선이 발생한다고 보장하지는 않는다. 이 결과는 **전이 방향이 잘못되지 않았다는 확인**으로 해석해야 한다.

검증 코드는 `bis-travel-time-practice/scripts/E37_check_student_data.py`, 요약 결과는 `bis-travel-time-practice/experiments/E37_saturday_check.csv`에 저장했다.


## 14. 해석과 한계

E37의 장점은 일요일 전체에 동일한 규칙을 적용하지 않고, 두 기존 예측의 차이를 불확실성 신호로 사용한다는 점이다. 또한 노선 ID를 사용하지 않고 노선 홀드아웃 검증을 했기 때문에 다른 노선으로의 전이를 직접 확인했다.

다만 연습 데이터와 대회 데이터의 노선 구성과 일요일 패턴이 완전히 같다는 보장은 없다. 특히 대회 B1 노선의 `route_type=7`은 연습 데이터에서 충분히 학습하지 못한 유형이다. 따라서 연습 검증 개선 폭이 public 또는 private 점수에 그대로 나타난다고 단정할 수 없다.

이 모델은 대회 test 정답을 사용하지 않았으며, 최종 결과는 리더보드 제출로 확인해야 한다.
