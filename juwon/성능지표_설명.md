# 성능 지표 정리

이 대회의 지표는 전부 **"초(sec)" 단위 오차**이고, **낮을수록 좋음.**

## 1. 지표 한눈에 보기

| 지표 | 뜻 | 순위에 쓰나 | 어디서 보나 |
|---|---|---|---|
| **MAE** | 평균 몇 초 틀렸나 | **순위 결정 (주 지표)** | 사이트 퍼블릭 / 마감 후 프라이빗 |
| RMSE | 크게 틀린 것에 벌점을 더 준 오차 | MAE가 같을 때만 (동점 처리) | 사이트 퍼블릭 |
| 첨두시간 MAE | 출퇴근 시간(7~9시, 17~19시)만의 MAE | 안 씀 (참고) | 대회 중 비공개, 내 검증으로 계산 |
| 노선별 MAE | 노선마다 따로 계산한 MAE | 안 씀 (참고) | 대회 중 비공개, 내 검증으로 계산 |
| MAPE (퍼센트 오차) | | **쓰지 않음** | 통행시간이 짧은 구간(10초 등)에서 값이 크게 튀어서 |

## 2. MAE (Mean Absolute Error, 평균 절대 오차)

**"예측이 실제와 평균 몇 초 차이 나는가."**

```
MAE = (|실제1 - 예측1| + |실제2 - 예측2| + ... ) / 행 수
```

예시:

| 구간 | 실제 | 예측 | 차이 |
|---|---|---|---|
| A→B | 60초 | 70초 | 10초 |
| B→C | 73초 | 63초 | 10초 |
| C→D | 112초 | 72초 | 40초 |

MAE = (10 + 10 + 40) / 3 = **20초** → "평균 20초씩 틀린다"

- 일찍 틀리든 늦게 틀리든 똑같이 차이만 봄.
- 직관적이라 이해하기 쉬움. MAE 27이면 "한 구간당 평균 27초 오차".
- MAE를 줄이려면 모델이 **중앙값**을 맞추도록 학습해야 함 → 그래서 LightGBM `objective='regression_l1'`(L1 = MAE)을 씀.

## 3. RMSE (Root Mean Squared Error)

**"크게 틀린 예측에 더 큰 벌점을 주는 오차."**

```
RMSE = √( (차이1² + 차이2² + ...) / 행 수 )
```

위 예시: √((10² + 10² + 40²) / 3) = √600 ≈ **24.5초**

- 차이를 제곱하므로 40초 하나가 10초 두 개보다 훨씬 크게 반영됨.
- **항상 RMSE ≥ MAE.** 둘의 차이가 클수록 "가끔 아주 크게 틀리는 구간이 있다"는 뜻.
- 우리 결과: MAE 27.7, RMSE 57.0 → RMSE가 2배 넘게 큼. 회차 구간이나 이상치(평소 100초 구간이 800초)처럼 **가끔 크게 틀리는 경우**가 있다는 뜻. 이런 건 원래 예측이 거의 불가능해서 어느 팀이나 비슷함.

## 4. 첨두시간 MAE / 비첨두 MAE

- **첨두:** 도착 시각이 7·8·9시, 17·18·19시인 행만 계산함.
- **비첨두:** 나머지 시간.
- 출퇴근 시간은 막혀서 예측이 어려움 → 보통 첨두 MAE가 더 큼.
- 우리 결과: 첨두 29.83 / 비첨두 26.48.

## 5. 노선별 MAE

- 노선마다 따로 계산함. 어느 노선에서 많이 틀리는지 보는 **오차 분석용**.
- 우리 결과(연습): 1번 33.35 / 102번 27.01 / 511번 25.33 / 605번 26.99 → 1번(급행)이 가장 어려움.

## 6. 퍼블릭 / 프라이빗

| | 퍼블릭 (30%) | 프라이빗 (70%) |
|---|---|---|
| 언제 보이나 | 대회 중 리더보드 | 마감(12/07) 후 |
| 용도 | 진행 상황 확인 | **최종 순위** |

- 어느 행이 어느 쪽인지는 비공개.
- **퍼블릭 점수만 보고 맞추면 위험함.** 30%에만 운 좋게 맞는 모델일 수 있어 프라이빗에서 떨어짐.
- 그래서 모델 선택은 **내 검증 점수(날짜별 4-fold `예상`)**로 하고, 퍼블릭은 확인용으로만 봄.

## 7. 어떻게 되면 좋은 건가

**MAE가 작을수록 좋음.** 기준은 아래 순서로 봄.

| 기준 | 연습 데이터 값 | 의미 |
|---|---|---|
| 평균 예측 (모델 없음) | test 29.89 / 검증 예상 31.33 | **이보다 나빠야 할 이유가 없음.** 교수님 '개선 점수'의 기준선 |
| 교수님 베이스라인 | test 28.05 | 실습 코드 그대로 → 개선 점수 8점 수준 |
| 우리 E5 | test 27.66 / 검증 예상 28.87 | 지금 위치 |
| 더 좋게 | ? | 개선 점수 15점까지, 순위 점수도 올라감 |

판단 요령:
- **검증 MAE가 0.1초 이상 줄면 의미 있는 개선**으로 봄. 0.05초 이하 차이는 잡음일 수 있음.
- **평일 점수와 토(주말) 점수를 따로 봄.** 하나만 좋아지고 다른 하나가 나빠지면 조심.
- **RMSE가 갑자기 커지면** 일부 구간에서 크게 틀리기 시작한 것 → 오차 분석 필요.
- 연습 데이터와 대회 데이터는 노선이 달라서 **숫자 자체는 비교 불가**. 대회에서는 대회 데이터의 평균 예측 대비 얼마나 줄였는지로 봄.
