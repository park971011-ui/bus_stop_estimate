# E94 일요일 회차 행 배율 보정 (검증은 4/4 통과, public은 나빠짐)

- 스크립트: `scripts/E94_sunday_turn_scale.py` (검증), 제출 파일 `submissions/final_E94_E89MD_sunturn.csv`
- 대회 public MAE: **24.144** (E89 MD 24.098 대비 **+0.046, 나빠짐**)
- 발표용 포인트: **"검증을 통과했는데 왜 실패했나"**

---

## 1. 한 줄 요약

> 연습 노선 4개 모두에서 "일요일 회차 대기는 모델 예측보다 22~26% 길다"가 나와서 대회 일요일 회차 행에 ×1.227을 곱했지만, **이 패턴이 대회 노선에는 옮겨 가지 않아** public이 나빠짐.

---

## 2. 발견 (E73 노선 빼기 검증 예측 분석)

- 일요일 회차 행은 일요일 행의 1.2%인데 **일요일 오차의 약 13%**
- 모델이 회차 행을 15~35% **짧게** 예측함 (연습 4개 노선 모두 일요일 회차 대기가 평일보다 김)
- 회차 아닌 행은 L1 최적 배율 0.95~1.01 → 치우침 없음

## 3. 보정 방법

- 회차 행만 × k. k = **나머지 3개 노선** 회차 행의 L1 최적 배율(가중 중앙값) → 1.22~1.26
- 노선 빼기 방식이라 k를 정할 때 그 노선 정답은 안 씀

| 일요일 MAE | 전체 | 1번 | 102번 | 511번 | 605번 |
|---|---|---|---|---|---|
| E73 | 27.340 | | | | |
| **E73 + 회차 ×k** | **26.860 (−0.480)** | −1.08 | −0.22 | −0.70 | −0.30 |
| 배율 반만 | 26.876 | | | | |

→ **4/4 노선 개선**, 일요일 모델 개선 중 가장 큰 폭. 비교로 E99(회차 피처를 모델에 넣기)는 27.084.

## 4. 제출

- E89 MD + 대회 일요일 회차 행 226행 × 1.227 (연습 4개 노선 전부로 정함), 평균 +184초
- 예상: 대회 일요일 회차 비율 0.73%(연습 1.15%)라 public 약 −0.05~−0.08
- **실제: 24.098 → 24.144 (+0.046)**. 바꾼 226행 중 public에 약 70행 → 행당 약 20초 더 틀린 셈

## 5. 발표에서 말할 것: 왜 실패했나

1. **노선 4개는 표본이 작음.** "4/4 노선"은 강해 보이지만 노선 4개짜리 일관성임. 회차 대기는 노선마다 운영 방식(차량 수·배차·기사 휴식)이 달라 노선 간 일반화가 특히 어려움
2. **경고 신호가 있었음.** 대회 노선 2·311은 **토요일 회차가 평일보다 짧았음** → 연습 노선과 반대 방향. 이걸 보고 멈췄어야 함
3. **곱하기 보정은 위험이 큼.** 회차 행은 값이 커서(수백 초) 배율이 조금만 틀려도 행당 오차가 큼. 피처로 넣는 방식(E99)은 모델이 알아서 조절함
4. **교훈:** 도메인이 다른 데이터(다른 노선)에서 찾은 규칙은, 대상 데이터(대회 노선)에서 **같은 방향인지 따로 확인**해야 함. 검증 점수만으로는 부족

### 같이 말하면 좋은 대비: E67은 성공
- E67도 연습 노선에서 찾은 규칙(일·토 배차 다른 노선만 일요일 가중치 ×2)이었는데 public −0.060으로 성공
- 차이: E67은 **노선의 입력 정보(배차 간격)로 조건을 걸어** 대회 노선에 맞게 적용, 가중치라 모델이 조절함. E94는 모든 대회 노선에 같은 배율을 **직접 곱함**
