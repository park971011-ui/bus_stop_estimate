# 평가 기준

| 평가 항목 | 배점 | 세부 배점 | 평가 방법 |
|---|---|---|---|
| 예측 성능 | 40 | 유효 제출 10, 개선 점수 15, 순위 점수 15 | 대회 사이트 자동 채점 (최종 지정 제출의 프라이빗 MAE) |
| 피처·분석 | 30 | 가설과 근거 10, 실험 기록 10, 오차 분석 10 | 발표 내용 |
| 발표 | 25 | 문제 이해와 구성 10, 결과 해석과 한계 10, 배운 점 5 | 최종 발표 |
| 재현성 | 5 | 실행되면 5, 아니면 0 | 제출한 노트북을 처음부터 끝까지 실행 |
| 합계 | 100 | | |


## 1. 예측 성능 채점

- 예측한 통행시간이 실제 통행시간과 평균 몇 초 차이 나는지(MAE)로 채점함. 값이 작을수록 잘 맞힌 것이고, 순위도 MAE로 정함. MAE가 같으면 RMSE가 작은 팀이 앞섬.

- MAE 말고도 아래 지표를 함께 계산함. RMSE는 MAE가 같을 때만 순위에 쓰고, 나머지는 순위에 쓰지 않음.

| 지표 | 뜻 |
|---|---|
| RMSE | MAE와 비슷하지만 크게 틀린 예측에 더 큰 벌점을 줌. MAE보다 많이 크면 가끔 크게 틀리는 구간이 있다는 뜻 |
| 첨두시간 MAE | 출퇴근 시간대(도착 시각이 7~9시대, 17~19시대)만 따로 계산한 MAE |
| 노선별 MAE | 노선마다 따로 계산한 MAE |

- 대회 사이트에서는 퍼블릭 MAE와 RMSE만 볼 수 있음. 첨두시간·노선별 MAE는 프라이빗 데이터까지 포함해 계산되기 때문에 대회 중에는 공개하지 않음. 필요하면 자기 검증 데이터로 직접 계산하면 됨.

- MAPE(퍼센트 오차)는 쓰지 않음. 통행시간이 10초처럼 짧은 구간에서는 조금만 틀려도 값이 크게 튀기 때문임.

- 개선 점수는 프라이빗 MAE가 모델 없이 같은 노선·방향·정류장·시간대의 평균 시간으로 예측했을 때의 MAE보다 작아야 받음. 대회 중에는 이 값을 각자 검증 데이터로 계산해 비교함.

## 2. 리더보드

대회 `test`는 하나의 파일이지만, 채점할 때 행을 **퍼블릭 30% / 프라이빗 70%** 로 나눔. 어느 행이 어느 쪽인지는 학생에게 알리지 않음.

| | 퍼블릭 | 프라이빗 |
|---|---|---|
| 점수 공개 | 대회 기간 중 리더보드에 표시 | 마감 후 공개 |
| 용도 | 진행 상황 확인 | **최종 순위** |

- 퍼블릭 점수만 올리는 모델은 프라이빗에서 순위가 떨어질 수 있음.
- 팀은 **하루 3회**까지 제출할 수 있음 (한국 시간 0시 초기화). 형식 오류로 채점되지 않은 제출은 횟수에 세지 않음.
- 팀은 제출한 것 중 최종 순위에 쓸 제출 1개를 대회 사이트에서 직접 고름. 고른 제출의 프라이빗 점수로 순위를 매기고, 고르지 않으면 퍼블릭 점수가 가장 좋은 제출이 자동으로 쓰임.
- 제출 방법: 대회 사이트에 로그인해 제출 화면에서 CSV(`row_id`, `tt_sec`)를 올림. CSV 1개가 든 zip도 되고, 30MB 이하. 사이트 주소는 https://am.dtumos.com/
- 모든 팀이 같은 노선을 풀기 때문에 MAE를 그대로 비교함.

## 3. 배점 세부

### 예측 성능 (40)

| 세부 | 점수 | 기준 |
|---|---|---|
| 유효 제출 | 10 | 형식에 맞는 최종 제출이 있으면 받음. 없으면 예측 성능 전체 0점 |
| 개선 점수 | 15 | 평균 예측보다 나아야 점수를 받기 시작함. 실습 코드를 그대로 낸 수준이면 8점, 더 개선할수록 15점까지 올라감 |
| 순위 점수 | 15 | 프라이빗 MAE 순위에 따라 1위 15점부터 꼴찌 8점까지 나눔 |

### 피처·분석 (30)

| 세부 | 점수 | 기준 |
|---|---|---|
| 가설과 근거 | 10 | 피처가 왜 도움이 될 것이라 생각했는지 |
| 실험 기록 | 10 | 시도한 것과 검증 점수 변화. 점수가 나빠진 실험도 포함 |
| 오차 분석 | 10 | 어느 노선·시간대·구간에서 많이 틀리는지와 원인 추정 |

### 발표 (25)

| 세부 | 점수 | 기준 |
|---|---|---|
| 문제 이해와 구성 | 10 | 예측 대상, 데이터 특징, 발표 흐름 |
| 결과 해석과 한계 | 10 | 결과가 나온 이유, 더 해 볼 수 있는 것 |
| 배운 점 | 5 | 예상과 달랐던 점, 다시 한다면 바꿀 것 |

## 4. 제출물

- 예측 CSV (`row_id`, `tt_sec`): 대회 사이트에 제출
- 노트북(`.ipynb`, 처음부터 끝까지 실행되는 상태)과 발표 자료: 사이버캠퍼스에 팀당 1명 제출

## 5. 규칙

- **허용 모델**: XGBoost, LightGBM, CatBoost, RandomForest, ExtraTrees, GradientBoosting 등 앙상블 계열.
- **외부 데이터**: 사용하지 않음. 수업에서 제공한 데이터(연습용·대회 데이터)만 씀.
- **검증**: 학습 데이터를 **날짜 단위**로 나눠야 함(예: 수요일을 검증용으로). 무작위 분할은 같은 시각의 앞뒤 버스가 섞여 성능이 실제보다 좋게 나옴.
- **정답 추정 금지**: 평가 데이터의 정답을 찾거나 추정하려는 시도는 허용하지 않음.
- **공유 금지**: 팀 밖에서 코드·예측을 공유하지 않음.
