# 버스 통행시간 예측 모델 평가 가이드

## 1. 무엇을 기준으로 모델을 선택할까?

이 프로젝트의 가장 중요한 평가 지표는 **날짜별 교차검증의 예상 MAE**이다.

MAE(Mean Absolute Error)는 모델이 예측한 통행시간과 실제 통행시간이 평균적으로 몇 초 차이 나는지 나타낸다.

- MAE 30초: 평균적으로 약 30초 틀림
- MAE 25초: 평균적으로 약 25초 틀림
- **값이 낮을수록 좋은 모델**

대회의 최종 순위도 MAE를 우선 사용한다. MAE가 같을 때만 RMSE가 작은 모델이 앞선다.

## 2. 왜 날짜별 교차검증을 사용해야 할까?

버스 데이터는 같은 날짜와 비슷한 시간대의 행들이 서로 강하게 연관되어 있다. 데이터를 무작위로 나누면 같은 시간대의 앞뒤 버스가 학습과 검증 데이터에 함께 들어가 실제보다 점수가 좋게 나올 수 있다.

따라서 현재 노트북처럼 학습 날짜 하나를 검증용으로 빼는 **날짜별 4-fold 교차검증**을 사용한다.

| 결과 열 | 의미 |
|---|---|
| `월`, `화`, `수`, `토` | 해당 날짜를 제외하고 학습했을 때의 검증 MAE |
| `평일` | 월·화·수 MAE의 평균 |
| `토` | 주말 성능을 확인하기 위한 토요일 MAE |
| `예상` | 실제 평가 데이터의 평일·주말 비율을 반영한 최종 비교 점수 |

현재 코드에서 예상 점수는 다음과 같이 계산한다.

```text
예상 MAE = 평일 MAE × 0.72 + 토요일 MAE × 0.28
```

## 3. 어떤 성능 지표를 봐야 할까?

### 1순위: 예상 MAE

모델과 피처를 선택할 때 가장 먼저 확인한다. 값이 낮을수록 좋다.

### 2순위: 날짜별 MAE의 안정성

예상 MAE가 낮더라도 특정 날짜에서만 좋고 다른 날짜에서 크게 나쁘면 불안정한 모델일 수 있다.

다음을 함께 확인한다.

- 월·화·수에서 모두 비슷하게 좋은가?
- 토요일 성능이 지나치게 나쁘지 않은가?
- 특정 fold 하나의 성능 향상만으로 전체 점수가 좋아진 것은 아닌가?

### 3순위: RMSE

RMSE는 가끔 매우 크게 틀리는 예측에 더 큰 벌점을 주는 지표이다.

- 모델들의 MAE 차이가 충분히 크면 MAE만 보고 선택한다.
- MAE가 거의 같으면 RMSE가 작은 모델을 선택한다.
- MAE보다 RMSE가 지나치게 크면 일부 구간에서 큰 오차가 발생하는지 확인한다.

### 보조 지표

- 첨두시간 MAE: 출퇴근 시간대에서 잘 맞는지 확인
- 노선별 MAE: 특정 노선에서만 성능이 나쁘지 않은지 확인
- 학습시간: 성능이 비슷할 때 빠른 모델을 선택하는 기준

## 4. 현재 실험 결과 해석

`experiments/results.csv`에 기록된 주요 결과는 다음과 같다.

| 실험 | 예상 MAE | 해석 |
|---|---:|---|
| E0 평균 예측 | 31.329초 | 모델을 사용하지 않은 기준선 |
| E1 LightGBM 기본 | 29.223초 | 기준선보다 개선됨 |
| E5 운행 순서 피처 | 28.870초 | 현재 유력한 피처 구성 |
| E6 시간대 운행 버스 수 | **28.832초** | 숫자상 현재 최고 |

E5와 E6의 차이는 **0.038초**로 매우 작다. 이 정도 차이만으로 E6가 확실히 더 좋다고 결론 내리기 어렵다. 날짜별 성능과 최종 데이터에서의 재현 여부를 함께 확인해야 한다.

구간 중앙값 target encoding을 추가한 E4는 29.436초로 오히려 나빠졌다. 따라서 피처는 많이 추가하는 것보다 교차검증에서 실제로 개선되는 피처만 유지해야 한다.

## 5. 어떤 모델을 비교할까?

모든 허용 모델을 전부 정밀 튜닝할 필요는 없다. 우선 다음 세 모델을 동일한 조건으로 비교한다.

### LightGBM

- 현재 기준 모델
- 학습이 빠르고 현재 검증 코드가 완성되어 있음
- E5 또는 E6 피처 구성으로 계속 사용

### CatBoost

- `route_id`, `vehicle_id`, `from_stop`, `to_stop`, `seg_id` 같은 범주형 변수가 많은 데이터에 적합
- 범주형 변수를 자체적으로 처리하므로 우선 비교할 가치가 큼
- LightGBM 다음으로 먼저 실험

### XGBoost

- 안정적이고 널리 사용되는 비교 모델
- LightGBM, CatBoost와 같은 fold와 피처를 사용해 한 번 비교
- 첫 비교에서 성능이 좋을 때만 추가 튜닝

RandomForest와 ExtraTrees는 시간 여유가 있거나 서로 다른 예측을 만드는 앙상블 후보가 필요할 때 추가한다.

## 6. 권장 실험 순서

1. E5 또는 E6의 피처 구성을 고정한다.
2. LightGBM, CatBoost, XGBoost에 동일한 날짜 fold를 적용한다.
3. 각 모델은 합리적인 기본 파라미터 한 세트로 먼저 실행한다.
4. 예상 MAE와 날짜별 안정성을 비교한다.
5. 성능이 좋은 상위 1~2개 모델만 추가로 튜닝한다.
6. 상위 두 모델의 예측 평균이 단일 모델보다 좋은지 OOF 예측으로 검증한다.
7. 최종 데이터가 공개되면 같은 비교를 다시 실행한다.

연습용 데이터와 최종 대회 데이터는 노선이 다르므로, 연습 데이터의 1등 모델을 최종 모델로 바로 확정하면 안 된다.

## 8. 최종 모델 선택 규칙

다음 순서로 판단한다.

1. 예상 MAE가 가장 낮은 모델을 찾는다.
2. 날짜별 점수가 안정적인지 확인한다.
3. MAE가 거의 같으면 RMSE가 작은 모델을 선택한다.
4. 성능도 비슷하면 코드가 단순하고 학습이 빠른 모델을 선택한다.
5. 두 모델을 섞었을 때 OOF MAE가 실제로 개선되면 앙상블을 선택한다.

## 9. 모델 선택에 사용하지 말아야 할 값

- 학습 데이터의 MAE
- 일반적인 `model.score()` 또는 R²
- Accuracy
- MAPE
- 연습용 test 점수를 반복 확인하면서 고른 결과
- 퍼블릭 리더보드 점수만 좋아지는 설정

연습용 test 점수와 대회 퍼블릭 점수는 마지막 확인 용도로만 사용한다. 모델과 피처 선택은 날짜별 교차검증 결과를 기준으로 한다.

## 한 줄 결론

> 동일한 날짜 교차검증에서 **예상 MAE가 가장 낮고 날짜별 점수가 안정적인 모델**을 선택한다. LightGBM을 기준으로 CatBoost와 XGBoost를 한 번씩 비교한 뒤, 상위 1~2개만 튜닝하고 앙상블을 검증한다.
