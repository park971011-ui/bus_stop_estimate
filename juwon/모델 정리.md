## 1. 문제 다시 보기

- **예측할 것:** 버스가 정류장 A에 도착한 순간부터 다음 정류장 B에 도착할 때까지 걸린 시간 `tt_sec`(초). A에서 정차한 시간도 포함.
- **채점:** MAE (평균 절대 오차)
- **가장 큰 함정:** 학습은 **월·화·수·토**, 평가는 **목·금·일**. **학습 데이터에 일요일이 없음** (test의 28%가 일요일).

참고: 모델 없이 노선·방향·정류장·시간대 평균으로만 예측하면 검증 27.641 → 우리 모델 25.2 수준.

## 3. 모델 구조 한눈에 보기

```
[1] 피처 35개 만들기 (기본 25개 + 회차 힌트 10개)
        │
[2] 모델 두 개 학습 후 섞기 = "E41 예측"
        LightGBM × 0.8  +  CatBoost × 0.2
        │
        ├── 목·금 행 ──→ E41 예측 × 0.5 + 평일 전용 LightGBM × 0.5
        │
        └── 일요일 행 ─→ 노선별로 섞기
                         · 211, 311:      토요일처럼 ½ + 평일처럼 ½
                         · 2, 704, B1:    토요일처럼 ⅓ + 평일처럼 ⅓ + 그대로 ⅓
```

### 모델 설정

| 모델 | 설정 |
|---|---|
| LightGBM | MAE(L1)로 학습, 나무 1500개, `learning_rate` 0.02, `num_leaves` 127, `min_child_samples` 10, subsample·colsample 0.8 |
| CatBoost | MAE로 학습, 2000회, `depth` 10, `learning_rate` 0.08, 노선·구간을 범주형으로 |
| 평일 전용 LightGBM | 위 LightGBM과 같은 설정, **월·화·수만 학습** (토요일 뺌) |

- **왜 MAE로 학습?** 채점이 MAE라서. `tt_sec`은 오른쪽 꼬리가 길어서(평균 113초, 중앙값 85초) MAE로 학습하면 중앙값 쪽으로 맞춰서 점수가 더 좋음.
- **왜 두 모델을 섞나?** 모델마다 틀리는 방식이 달라서 섞으면 실수가 서로 조금 상쇄됨. 0.8은 검증으로 고른 비율 (0.7·0.9보다 좋았음).

## 5. 핵심 아이디어 3가지

### 5-1. 일요일 섞기 (E35 → E45) — public −0.22

**문제:** 모델은 일요일을 처음 봄. 그냥 넣으면 "주말 = 토요일"로 생각해서 토요일처럼 예측함.
그런데 실습 데이터로 보니 **일요일은 토요일보다 더 한산함** (평균 tt_sec: 평일 116.9초, 토 115.2초, 일 108.0초).

**해결:** 일요일 행을 두 번 예측해서 섞음.

| 예측 방법 | 주말 여부 | 배차 간격 |
|---|---|---|
| 토요일처럼 | 주말 | 토요일 배차 |
| 평일처럼 | 평일 | 평일 배차 |

→ 둘을 반반 섞으면 "토요일보다 조금 빠른" 일요일 모양이 됨.

**E45에서 노선별로 다듬음:** 일요일 배차가 토요일보다 긴 노선(2, 704, B1)은 "그대로(주말·일요일 배차)" 예측을 ⅓ 더 넣음. 실제로는 토요일 쪽 비중이 ⅔로 늘어난 효과. 배차 값만 보고 미리 정한 규칙이라 정답은 안 씀.

### 5-2. 회차 구간 힌트 (E41) — public −0.20

**문제:** 회차 구간(종점에서 쉬었다 출발하는 구간)은 전체 행의 0.67%뿐인데, 오차가 평균 224초라서 **전체 오차의 약 6%**를 차지함. 쉬는 시간은 데이터에 없음.

**아이디어:** 같은 버스의 **다음 운행(반대 방향)이 몇 시에 시작하는지**는 test에도 있음. 오래 쉬면 다음 운행이 다음 시간으로 넘어감.
- 다음 운행이 같은 시에 시작 → 중앙값 596초
- 다음 운행이 다음 시에 시작 → 중앙값 788초

**넣은 피처 10개 (회차 구간 행에만):** 다음 운행 시작까지 몇 시간인지, 그 시간의 행 수, 그 버스의 그 시·앞 시·뒤 시 행 수, 같은 시간대 안의 구간 수·거리, 앞 구간과의 시각 차이 등.

**결과:** 회차 행 오차 224초 → 199초. 나머지 행은 그대로. 검증(−0.173), 실습 모의고사(−0.268), public(−0.198)이 모두 같은 방향이라 믿을 만함.

### 5-3. 목·금은 평일 전용 모델과 반반 (E44) — 검증 −0.07

- 월·화·수만으로 학습한 LightGBM을 따로 만들어서 목·금 예측에 E41과 반반 섞음.
- 대회 train 검증에서 평일 3일 **모두** 좋아짐 (평균 −0.072), 실습 목·금도 −0.054.
- 평일 전용 모델 혼자서는 별로 안 좋음 → 효과의 상당 부분은 "조금 다른 모델 두 개를 섞은 효과"로 보임.

## 6. 검증 방법

- **대회 train 날짜별 4-fold:** 하루씩 빼고 나머지 3일로 학습 → 뺀 날 예측.
- **비교 점수 `예상` = 평일 MAE × 0.72 + 토 MAE × 0.28** (test가 목·금 72%, 일 28%라서).
- **실습 데이터 = 모의고사:** 대회와 날짜 구성이 똑같고(월·화·수·토 → 목·금·일) test 정답이 있음. 새 방법은 **미리 정한 설정으로 한 번만** 시험하고, 점수를 보고 비율을 다시 고르지 않음 (과적합 방지).

| | 대회 train 검증 `예상` | 실습 모의고사 | public |
|---|---|---|---|
| E32 / E35 | 25.402 | 27.395 (E35) | 25.028 / 24.808 |
| E41 | 25.229 | 27.127 | 24.610 |
| **E46** | (목·금 −0.052 추정) | **27.039** | **24.577** |

## 7. 해 봤는데 안 된 것

| 시도 | 결과 | 이유 |
|---|---|---|
| 피처 더 넣기 (역 정류장, 주말×시간 등) | 검증만 좋고 test는 나빠짐 | 토요일 패턴만 외워서 일요일엔 안 맞음 |
| 차량(버스) ID 피처 | 나빠짐 | 버스끼리 차이가 작고 과적합 |
| 노선별로 모델 따로 | 나빠짐 | 데이터가 쪼개져서 약해짐 |
| XGBoost 섞기 | 비중 0 | 혼자서도 가장 약했음 |
| Huber 손실 | +0.605 나빠짐 | MAE 채점에는 L1이 맞음 |
| 잔차 학습, 사후 보정 | 효과 없음 | 모델이 이미 잘 잡고 있음 |
| seed 5개 평균 (E47) | 검증 −0.015, 실습 +0.002 | 효과가 흔들림 수준 → 제출 안 함 |
| 직전 시간대 이동 피처 (E51) | 평일 3일 모두 나빠짐 | |
| 회차 구간을 규칙(노선×시간 평균)으로 예측 | 검증·실습 결과가 반대 | 믿기 어려워서 힌트 피처로 바꿈 |

**왜 더 크게 안 줄어드나:** 남은 오차 대부분이 **신호 대기**와 **종점 대기**에서 나옴. 데이터에 신호 정보가 없어서 어떤 모델로도 맞히기 어려움.

## 8. ⚠️ 주의할 것

1. **E37(public 24.798)은 최종으로 고르면 안 됨.**
   실습 test 일요일 정답으로 보정했는데, 실습 test 일요일과 대회 test 일요일이 **같은 날(9/29)**이라 "평가 데이터 정답 추정"으로 볼 수 있음. 점수 차이도 0.01로 의미 없음.
2. **public은 test의 30%만으로 낸 점수.** 최종 순위(private 70%)는 다를 수 있음. 그래도 E46은 검증·모의고사·public이 모두 같은 방향이라 가장 안전한 선택.
3. **MLP 같은 신경망은 규칙 위반** (앙상블 계열만 허용).
