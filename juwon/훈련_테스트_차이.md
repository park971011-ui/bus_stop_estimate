# 훈련 데이터와 테스트 데이터의 차이

연습 데이터(`data/practice/`)로 확인한 내용. 대회 데이터도 구조가 같음(학습 월·화·수·토, 평가 목·금·일).

## 1. 한눈에 비교

| 항목 | train (훈련) | test (평가) |
|---|---|---|
| 날짜 | 9/23 **월**, 9/24 **화**, 9/25 **수**, 9/28 **토** | 9/26 **목**, 9/27 **금**, 9/29 **일** |
| 평일 / 주말 | 평일 3일 + 토요일 1일 | 평일 2일 + **일요일 1일** |
| 행 수 (연습) | 109,891 | 79,942 |
| 행 수 (대회) | 154,327 | 111,563 |
| 정답 `tt_sec` | 있음 | 연습: 있음(직접 채점용) / **대회: 없음** |
| 노선 | 같음 (연습 4개, 대회 5개) | 같음 |
| 운행 시간대 | 5~23시 | 5~23시 |
| 차량 | 89대 | 83대 (99%가 train에도 나옴) |
| 구간(정류장→정류장) | 272개 | 274개 (train에 없는 구간 2개, 행 비율 0.003%) |
| 노선 고정 정보 (배차간격, 첫차·막차) | 같음 | 같음 |

**핵심:** 일주일 7일이 다 있는 게 아님. 훈련과 평가가 **요일 단위로 나뉘어** 있어서 요일이 하나도 겹치지 않음.

## 2. 날짜별 행 수와 통행시간

| 날짜 | 요일 | 구분 | 행 수 | 평균 tt_sec | 중앙 tt_sec |
|---|---|---|---|---|---|
| 9/23 | 월 | train | 28,783 | 116.7 | 89 |
| 9/24 | 화 | train | 28,870 | 117.0 | 91 |
| 9/25 | 수 | train | 28,887 | 116.7 | 90 |
| 9/26 | 목 | test | 28,853 | 116.6 | 90 |
| 9/27 | 금 | test | 28,713 | 117.8 | 91 |
| 9/28 | 토 | train | 23,351 | 115.2 | 85 |
| 9/29 | 일 | test | 22,376 | **108.0** | **78** |

- **평일은 날마다 거의 같음.** 평균 116~118초. 그래서 월·화·수로 배운 게 목·금에 잘 통함.
- **주말은 배차가 줄어 행 수가 약 20% 적음.**
- **일요일이 가장 빠름.** 토요일보다 평균 7초, 중앙값 7초 짧음. 하지만 훈련 데이터에 일요일이 없어서 모델은 일요일을 "토요일과 비슷하겠지"라고 추정할 수밖에 없음.

## 3. 이 차이 때문에 생기는 문제

1. **요일(`dow`)을 그대로 피처로 쓸 수 없음.** 훈련에 목·금·일이 아예 없어서 모델이 그 값을 한 번도 본 적이 없음. 대신 `is_weekend`(주말 여부)처럼 묶어서 씀.
2. **일요일 예측이 가장 어려움.** 연습 데이터에서 베이스라인 LightGBM의 test MAE는 목 26.4, 금 27.8, **일 30.5**. 점수를 올릴 여지가 가장 큰 곳.
3. **무작위 분할 검증은 점수를 실제보다 좋게 보여줌.** 같은 날 같은 시각의 앞뒤 버스가 훈련과 검증에 섞이기 때문. 평가는 "본 적 없는 날"을 맞히는 문제라서 검증도 날짜 단위로 나눠야 함 (대회 규칙에도 있음).

## 4. 훈련 데이터 나누는 법 (검증)

훈련 날짜 4개를 하나씩 돌아가며 검증에 쓰는 **날짜별 4-fold**를 추천.

| fold | 학습 | 검증 | 이 fold가 알려주는 것 |
|---|---|---|---|
| 1 | 화·수·토 | **월** | 평일 성능 (→ 목·금 예상) |
| 2 | 월·수·토 | **화** | 평일 성능 |
| 3 | 월·화·토 | **수** | 평일 성능 |
| 4 | 월·화·수 | **토** | 주말 성능 (→ 일요일 예상, 다만 이때는 학습에 주말이 0일이라 실제보다 더 어려움) |

- 점수는 **4개 평균**과 함께 **평일 평균(fold 1~3)**과 **토요일(fold 4)**을 따로 기록함.
- 평가 행은 평일(목·금)이 약 72%, 주말(일)이 약 28%이므로, 대략 `평일 평균 × 0.72 + 토요일 × 0.28`로 계산한 값이 실제 점수와 가장 비슷함.
- 수요일 하나만 검증하면(노트북 기본) 주말 성능을 전혀 알 수 없어서 부족함.
- 최종 제출용 모델은 **train 4일 전체**로 다시 학습함.
- **누수 주의:** 구간별 평균 같은 집계 피처는 fold마다 **학습 날짜로만** 계산해야 함. 검증 날짜까지 넣어 계산하면 점수가 부풀려짐.

## 5. 어떤 모델을 쓸까

규칙상 앙상블 계열만 가능 (XGBoost, LightGBM, CatBoost, RandomForest, ExtraTrees, GradientBoosting 등).

| 모델 | 추천 용도 | 이유 |
|---|---|---|
| **LightGBM** | **메인 모델 (먼저 시작)** | 빠름(한 fold 수 초). MAE를 직접 줄이는 `objective='regression_l1'` 지원. 범주형 처리 가능. 피처 실험을 많이 돌리기 좋음 |
| CatBoost | 두 번째 모델 | 정류장·구간 ID 같은 범주형을 잘 다룸. `loss_function='MAE'`. 느리지만 성능이 좋을 때가 많음 |
| XGBoost | 비교용 | `objective='reg:absoluteerror'`. LightGBM과 비슷한 계열 |
| RandomForest / ExtraTrees | 앙상블 재료 | 단독 성능은 보통 낮지만 섞으면 도움이 될 수 있음 |

진행 순서 추천:
1. **LightGBM 하나로** 검증 틀과 피처 실험을 먼저 끝냄 (빨라서 실험을 많이 돌릴 수 있음).
2. 피처가 정해지면 CatBoost, XGBoost를 같은 피처로 비교함.
3. 마지막에 예측을 평균 내는 앙상블을 시도함.

**손실 함수는 MAE(L1)로 맞춤.** 정답 분포가 오른쪽으로 길게 늘어져 있어서(중앙 89초, 최대 1775초) 기본값인 MSE로 학습하면 이상치에 끌려가 MAE가 나빠짐.
