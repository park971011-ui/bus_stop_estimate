## 2. 모델 구조 (3단계)

```
[1단계] 피처 25개 만들기
          ↓
[2단계] 두 모델 학습 후 섞기
        LightGBM 예측 × 0.8  +  CatBoost 예측 × 0.2
          ↓
[3단계] 일요일 행만 따로 처리
        (토요일처럼 예측 + 평일처럼 예측) ÷ 2
        목·금 행은 2단계 결과 그대로
```

### 왜 두 모델을 섞나
모델마다 틀리는 방식이 달라서, 섞으면 실수가 서로 조금씩 상쇄됨. 섞는 비율 0.8은 대회 train 검증으로 골랐음 (0.7·0.9보다 좋았음).

| 모델 | 주요 설정 |
|---|---|
| LightGBM | MAE로 학습, 나무 1500개, `learning_rate` 0.02, `num_leaves` 127, `min_child_samples` 10 |
| CatBoost | MAE로 학습, 2000회, `depth` 10, `learning_rate` 0.08 |

## 4. 핵심 아이디어: 일요일 반반 섞기

**문제:** 학습 데이터는 월·화·수·토, 평가는 목·금·일. **학습에 일요일이 없음.**
그래서 모델이 일요일을 토요일처럼 예측함.

**분석으로 알게 된 것 (연습 데이터):**
- 일요일은 토요일보다도 3~5% 빨랐음 (더 한산함)
- 모델은 일요일의 58%를 실제보다 길게 예측했음 (평일은 반반)
- 일요일 오차(30.5)가 평일(25.6~27.0)보다 3~5초 큼

**한 것:** 일요일 행을 두 번 예측해서 평균 냄.

| | 주말 여부 | 배차 간격 |
|---|---|---|
| 토요일처럼 | 주말 | 토요일 배차 |
| 평일처럼 | 평일 | 평일 배차 |

**결과:**
- 연습 데이터 모의고사: 27.473 → 27.395
- 대회 public: 25.028 → **24.808 (-0.22)**
- 바뀐 건 일요일 행뿐이라, 좋아진 건 전부 일요일 덕분

> 연습 데이터는 대회와 구조가 똑같아서(월·화·수·토 학습 → 목·금·일 예측) **모의고사**로 썼음. 섞는 비율 0.5는 미리 정하고 한 번만 시험함.

## 5. 해 봤는데 안 된 것

| 시도 | 결과 | 이유 |
|---|---|---|
| 피처 더 넣기 (역 정류장, 주말×시간 등 9가지) | 검증만 좋고 test는 나빠짐 | 토요일 패턴만 외워서 일요일엔 안 맞음 |
| 버스(차량)별 피처 | 나빠짐 | 버스끼리 차이가 작음. 정답을 알아도 최대 0.15초 |
| 회차 구간(종점 대기) 피처 | 효과 0 | 모델이 구간 ID로 이미 알고 있음 |
| XGBoost 섞기 | 비중 0 | 혼자서도 가장 약했음 |
| 노선별로 모델 따로 | 나빠짐 | 데이터가 쪼개져서 약해짐 |

**왜 더 크게 안 줄어드나:** 남은 오차 대부분이 **신호 대기(약 60초 vs 180초)**와 **종점 대기**에서 나옴. 데이터에 신호 정보가 없어서 어떤 모델로도 맞히기 어려움.
