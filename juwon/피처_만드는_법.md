# 피처 잘 만드는 법

피처를 잘 만든다 = **"버스가 왜 늦어지는지"를 생각해서 그걸 숫자로 바꿔 주는 것.**
모델은 우리가 준 숫자만 볼 수 있어서, 중요한 원인을 숫자로 만들어 주면 그만큼 잘 맞힘.

## 1. 기본 순서: 가설 → 만들기 → 검증 → 기록

```
① 가설   "운행이 길어지면 지연이 쌓여서 느려질 것이다"
② 만들기  seq_in_trip = 운행 안에서 몇 번째 구간인지
③ 검증   4-fold 예상 점수: 28.93 → 28.87 (좋아짐)
④ 기록   실험기록.md에 가설·결과 적기 (나빠져도 기록)
```

이 순서를 지키면 **발표 점수(가설과 근거 10점, 실험 기록 10점)가 자동으로 쌓임.**

## 2. 아이디어 얻는 방법

### ① 현실을 상상하기 (도메인 지식)
"버스가 A에서 B까지 갈 때 시간을 잡아먹는 게 뭘까?"
- 정차 시간: 손님이 많은 정류장(환승역, 대학교, 시장)
- 신호등: 큰 교차로, 사거리
- 혼잡: 출퇴근, 도심
- 회차: 종점에서 대기

### ② 많이 틀리는 곳 보기 (오차 분석) ← 가장 효과적
모델이 크게 틀리는 행을 뽑아서 공통점을 찾음. 지금 알고 있는 약점:
- **토·일요일:** 36점대로 평일(26점대)보다 훨씬 나쁨
- **1번 급행 노선:** 33점으로 가장 많이 틀림
- **첨두 시간:** 29.8점으로 비첨두(26.5점)보다 나쁨

→ "왜 여기서 틀릴까?"를 고민하면 다음 피처 아이디어가 나옴.

### ③ 데이터 들여다보기
정류장 이름, 지도 위 좌표, 한 버스의 하루 기록을 직접 보면 힌트가 보임.

## 3. 이 데이터로 만들어 볼 만한 피처

| 가설 | 피처 아이디어 | 만드는 법 |
|---|---|---|
| 큰 정류장은 정차가 길다 | 정류장 이름에 `역`, `네거리`, `터미널`, `병원`, `대학` 포함 여부 | `from_name` 문자열 검사 |
| 여러 노선이 서는 정류장은 붐빈다 | 출발 정류장을 지나는 노선 수 | `from_stop`별 `route_id` 고유 개수 |
| 도심은 막힌다 | 대전 도심(예: 대전역·시청)까지 거리 | 좌표로 거리 계산 |
| 출발점에서 멀어질수록 지연이 쌓인다 | 노선 시작부터 누적 거리 | `stop_seq` 순서로 `dist_m` 누적합 |
| 방향이 꺾이면 느리다 | 구간 진행 방향(각도), 앞 구간과의 꺾임 | `dlat`, `dlon`으로 각도 계산 |
| 주말은 시간대 패턴이 다르다 | 주말 × 시간대 조합 | `is_weekend * 100 + arrive_hour` |
| 막차 근처는 빠르다 | 막차까지 남은 시간 | `last_min - arrive_hour*60` |

이 표는 아직 가설일 뿐. **실제로 좋아질지는 검증을 돌려 봐야 앎.** E4(구간 중앙값)처럼 좋을 것 같았는데 나빠지는 경우도 많음.

## 4. 꼭 지켜야 할 규칙

| 규칙 | 이유 |
|---|---|
| **test에서도 계산할 수 있어야 함** | 대회 test에는 `tt_sec`가 없음. "앞 구간에서 걸린 시간" 같은 건 못 씀 |
| **정답으로 만든 피처는 학습 날짜로만 계산** | 검증 날짜의 정답이 섞이면 점수가 실제보다 좋게 나옴 (누수) |
| **요일 원본은 쓰지 않음** | train(월화수토)과 test(목금일)의 요일이 하나도 겹치지 않음 |
| **한 번에 하나씩 추가** | 여러 개를 한꺼번에 넣으면 뭐가 도움이 됐는지 모름 |
| **0.1초 이상 좋아져야 채택** | 그보다 작은 차이는 우연일 수 있음 |
| **외부 데이터는 쓰지 않음** | 대회 규칙 (날씨, 지도 API 등 금지) |

## 5. 다음 할 일: 오차 분석부터

지금 가장 효과가 클 곳은 **주말 성능**. 오차 분석으로 "토요일에 어떤 구간·시간대에서 크게 틀리는지" 확인하고, 거기에 맞는 피처를 만듦.
